# План разработки «Последнего сигнала»

## Принцип первой версии

Сначала один устойчивый игровой цикл: зайти вдвоём → найти детали → восстановить питание → столкнуться с сущностью → передать сигнал → вернуться в лобби. Не добавлять большую карту, пока этот цикл не проходит несколько раз подряд на двух физических компьютерах.

Прототип 0.2 в этой папке уже реализует этот цикл и содержит 24 собственные модели, фактуры и атмосферные звуки. Дальнейший план — его проверка, улучшение и расширение. Оценки времени ориентировочные для новичка, а не обещание готовой игры за месяц.

## Этапы от прототипа до первой играбельной версии

| Этап | Результат | Условие перехода |
|---|---|---|
| 1. Технический прототип | LAN, движение, один предмет, одна цель | Хост и клиент видят одно состояние |
| 2. Полный короткий цикл | Генератор, кассета, простая сущность, общий финал | Две команды проходят раунд без помощи разработчика |
| 3. Вертикальный срез | Оформленная радиорубка, звук, 2–3 события, читаемый интерфейс | Игрок понимает задачи и боится сущности |
| 4. Расширение станции | Подвал, два маршрута, укрытия, несколько генераторов | Есть выбор и командное разделение, нет тупиков |
| 5. Баланс и оптимизация | 15–30 минут, осмысленные роли, стабильная производительность | Измерения на целевом ноутбуке и 2–4 ПК |
| 6. Первая версия для друзей | Windows-сборка, инструкция, исправления | Полный чек-лист LAN и повторных раундов пройден |

В первой версии достаточно одной карты, одного врага и одного сценария. Процедурные уровни, прогрессия, интернет и множество монстров сильно увеличат сложность.

## Первая неделя

| День | Действия | Что проверить руками |
|---|---|---|
| 1 | Открыть готовый проект, пройти учебный запуск, посмотреть Remote-дерево | WASD, F, батарея, подсказки, настройки, Esc |
| 2 | Запустить две копии на одном ПК, затем на двух ПК | IP, порт, роли, совпадение движения и позиций |
| 3 | Пройти предметы, ключ, генератор и финал | Нет дубликатов; расход предметов одинаков; оба нужны у финала |
| 4 | Разобрать MonsterAI и настроить скорость/дистанции | Можно убежать; стены и закрытые двери мешают; фонарь помогает |
| 5 | Записать в Audacity 5–8 звуков, заменить часть заглушек | Шаги не заглушают важные сигналы; помехи не слишком громкие |
| 6 | Собрать 2–3 простые модели в Blender, оформить одну комнату | Масштаб 1 м, корректный экспорт GLB, простые коллизии |
| 7 | Сыграть вдвоём несколько раундов и составить список проблем | Подбор одновременно, отключение, смерть, победа, повторный раунд |

Минимальная цель недели — стабильная короткая LAN-игра на двух физических компьютерах. Если сеть или интерфейс ломаются, день с моделями отложить до исправления.

## Первый месяц

| Неделя | Добавления | Ограничение объёма |
|---|---|---|
| 1 | Проверка и понимание готового прототипа, первые свои звуки | Одна карта и текущий сценарий |
| 2 | Выделение UI в отдельные сцены, 1–2 законченные комнаты, настройки звука | Не переделывать всю станцию одновременно |
| 3 | Подвал, одно настоящее укрытие, второй генератор, связанное усиление сущности | Сначала 2 игрока, затем 3–4 |
| 4 | Баланс ролей, 15–30 минут, оптимизация, Windows-экспорт, тесты друзей | Новые механики только после исправления критичных ошибок |

Если работа идёт медленнее, сохранить приоритет: сеть → игровой цикл → читаемость → атмосфера → расширение. Хороший маленький уровень полезнее большой неработающей станции.

## Роли: сейчас и дальше

| Роль | В прототипе | Развитие |
|---|---|---|
| Техник | Ремонт в 1.8 раза быстрее, движение на 10% медленнее, 4 слота | Отдельные схемы ремонта и инструменты |
| Разведчик | 3 слота, предупреждение о близкой сущности | Следы и звуки направления; убрать прямое знание дистанции |
| Медик | Поднятие за 3 с вместо 6 с, более сильная аптечка, не носит бензин | Лечение союзника, перенос лёгкого набора |
| Оператор | Базовые возможности общих устройств | Карта, рация, ускоренная передача, цена уязвимости |
| Техник-разведчик | Бонус ремонта, предупреждение, 4 слота, сниженная скорость | Баланс для двух участников |
| Медик-оператор | Поднятие/аптечка, 3 слота, запрет канистры | Карта/рация и защита во время работы |

Сейчас специальные возможности оператора ещё не выделены. Втроём любая команда должна справляться без обязательного класса: обычный ремонт и поднятие доступны всем.

## Следующие механики

1. Укрытие: сервер проверяет вход, закрывает позицию игрока для зрения, но оставляет слышимость шума. Выход проверяет свободное место.
2. Второй генератор: хранить список генераторов с отдельными ресурсами и состоянием; активность сущности рассчитывать по их числу. Финальный щит не заменяет дополнительный генератор.
3. Кассеты: сначала три небольшие записи с текстовыми субтитрами, затем развилки сюжета. Не требовать прослушивания длинного файла ради прохождения.
4. Ложные события: выбирать событие на хосте и рассылать ID/позицию; звук воспроизводить локально. Не запускать несогласованные случайные события на каждом клиенте.
5. Рация: сначала готовые фразы и сигналы, затем отдельный голосовой тракт с push-to-talk. V в 0.1 — игровой шумовой сигнал.
6. Смерть: камера наблюдения за союзниками, отдельный экран, безопасная смена наблюдаемого при отключении.

## Частые ошибки

| Ошибка | Как избежать |
|---|---|
| Код из Godot 3 с `master`, `remote`, `KinematicBody` | Использовать Godot 4: `@rpc`, `CharacterBody3D`, ENetMultiplayerPeer |
| Клиент сам добавляет предмет в инвентарь | Клиент передаёт намерение; хост проверяет луч и меняет состояние |
| Хост принимает координаты клиента | Передавать ввод и считать перемещение с коллизиями на хосте |
| Имя персонажа отличается в каждом процессе | Назвать его строкой peer_id до добавления в дерево |
| Всем камерам установлено `current` | Только камера локального peer_id |
| Спавн начат до загрузки клиента | Барьер готовности каждого участника |
| В `spawn_function` вызывается `add_child` | Вернуть ещё не добавленную ноду; добавляет спавнер |
| Authority передана клиенту вместе с уроном и инвентарём | Держать authority у хоста; владельца ввода хранить отдельно |
| RPC разрешён `any_peer`, но отправитель не проверен | Вычислять персонажа по remote_sender_id, проверять этап и номер раунда |
| Все события идут надёжно 60 раз/с | Частый ввод/позиции — заменяемые данные; критичные события — reliable |
| Карта удалена на клиенте раньше серверного despawn | Сначала остановка, затем despawn и подтверждение, затем удаление карты |
| Выход в меню ставит весь SceneTree на паузу | Блокировать локальный ввод; сеть и мир продолжаются |
| Проверили только один запуск | Обязательно второй раунд и отключение игрока с важными предметами |
| В LAN используют внешний IP роутера | Использовать локальный IPv4 активного адаптера |
| Сначала сложный реалистичный арт | Сначала доказать, что короткий цикл понятен и проходим |

## Условия первой версии для друзей

- Новая команда может пройти раунд по подсказкам в игре.
- Существуют и победа, и поражение; важные предметы не теряются при выходе клиента.
- 2, 3 и 4 участника могут закончить несколько раундов подряд на физических ПК.
- Смерть и выход одного участника не оставляют остальных без доступной цели.
- Настройки читаемы, сохраняются, быстрый пресет подходит целевому ноутбуку.
- Лицензии всех добавленных ассетов записаны; ссылки и авторство сохранены.
- У Windows-сборки есть название версии, инструкция подключения и список известных проблем.
