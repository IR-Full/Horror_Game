# Как проверить проект

Проверено 28 октября 2026 года на установленном Godot `4.7.2.stable.official.ed1daf0bf`: сценарии для 2, 3 и 4 локальных процессов завершились с PASS. После исправления завершения раунда заключительный запуск вчетвером прошёл без ошибок и предупреждений. Проверка рендера меню, станции и настроек также прошла.

После оформления 0.2 повторно прошли LAN-сценарии на 2 и 4 процесса. Проверка `--art-check` подтвердила импорт 24 моделей, открытые маршруты, согласованность дверных коллизий и навигации, работу трёх пресетов, исчезновение ложного силуэта и генерацию новых звуков.

Для 0.3 расширена проверка 29 моделей: пять анимаций сущности, понижение головы и тела в позе на четвереньках, переход к настоящей серверной погоне с низкой коллизией, шесть луж и три надписи. LAN-сценарий на четырёх процессах прошёл после смены модели и схемы синхронизации. Визуально проверены вертикальная и низкая позы, следы крови, свет и дополнительная обстановка.

## Автоматические проверки

Тесты запускают отдельные настоящие процессы Godot и подключают их через ENet/UDP на `127.0.0.1`. Это проверка нескольких экземпляров на одном компьютере; она не заменяет Wi-Fi и брандмауэр на двух физических ПК.

Откройте PowerShell в корне проекта:

```powershell
python tools/run_smoke.py --players 2
python tools/run_smoke.py --players 3 --port 27943
python tools/run_smoke.py --players 4 --port 27942
```

Если Godot перемещён:

```powershell
python tools/run_smoke.py --players 2 --godot 'D:\Godot\Godot_console.exe'
```

Python используется только как инструмент запуска тестов. Вся игровая логика написана на GDScript. В headless-режиме не запускается воспроизведение звука. Для каждого процесса создаётся отдельная папка настроек под `test-results/`, поэтому тесты не перезаписывают настройки обычной игры.

Результат должен содержать `PASS` для каждого процесса, код завершения 0 и не содержать `ERROR:`. Логи находятся в `test-results/lan-2/`, `lan-3/` и `lan-4/`.

Проверки охватывают:

- подключение, состав команды, допустимость роли и сетевой спавн;
- ввод клиента → движение на хосте → полученную клиентом позицию;
- ограничение величины ввода, отбрасывание NaN, коллизии наружной стены;
- неподходящий номер раунда и невозможность изменить другого персонажа через ввод;
- дальность и направление луча подбора, защиту от повторного подбора;
- расход бензина и предохранителя, ремонт, ключ и дверь архива;
- доставку состояния предметов и генератора на клиенты;
- реакцию сущности на шум, видимость и направленный фонарь;
- восстановление батареи и базовое поднятие;
- отсутствие прогресса финала у одиночного оператора в живой команде;
- совместное удержание устройств двумя разными участниками и общую победу;
- отключение клиента, выкладывание его вещей и удаление персонажа;
- возвращение в лобби, очистку мира и новые раунды;
- поражение по времени и при оглушении всей команды.

Сценарий специально переставляет игроков на хосте между точками, чтобы быстро пройти все стадии. Это не тест честного прохождения маршрута и не измерение сложности игры. ИИ в сетевом сценарии останавливается; его основные реакции проверяются отдельно внутри того же мира. Длинную погоню и застревания нужно проверять вручную.

## Визуальная проверка

```powershell
$env:APPDATA = Join-Path (Get-Location) 'test-results\preview-runtime'
& 'C:\Users\Huawei\Downloads\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe' --path . --resolution 1152x648 -- --preview
```

Эта команда временно открывает игру, сохраняет реальные кадры меню, станции, склада, радиорубки, генератора, сущности и настроек в `test-results/*.png`, затем закрывает её. Для снимков нужен обычный графический запуск, без `--headless`. Изменение APPDATA действует в текущем окне PowerShell; для обычной игры используйте стартовый `.cmd` из нового окна или восстановите переменную окружения.

Проверка оформления без графического окна: тот же исполняемый файл с `--headless --path . -- --art-check`. Ожидаемый результат — `ART_PASS`, код завершения 0.

Кадры проверялись с рендерером Compatibility на Intel UHD. Это подтверждает отображение интерфейса и сцены, но не является полноценным замером производительности. Число FPS на одном кадре не используйте как обещание стабильного FPS.

## Ручной чек-лист перед передачей друзьям

1. Один учебный раунд: взять реальные предметы без тестовых перемещений и дойти до победы.
2. Два компьютера в одной сети: создать комнату, сменить роли, завершить игру.
3. По очереди нажать E на одном предмете с двух клиентов: получить одну копию.
4. Выключить фонарь, побежать, закрыть дверь и попробовать спрятаться. Сущность не должна проходить сквозь стены.
5. Оглушить одного игрока, поднять его другим; проверить точную дальность и непрерывное удержание.
6. Отключить игрока с кассетой: оставшиеся должны найти её на полу.
7. Закрыть приложение хоста: клиенты должны вернуться в меню с сообщением.
8. Выйти и повторно подключиться в лобби. Проверить второй и третий раунды.
9. Изменить графику, громкость, масштаб и чувствительность. Перезапустить обычную игру, проверить сохранение.
10. Повторить на 3–4 физических ПК и слабом Wi-Fi; записать ошибки, пинг, пресет и версию сборки.

## Экспорт для Windows

1. В Godot откройте **Editor → Manage Export Templates** и установите шаблоны, совпадающие с версией движка. Они не требуются для `StartGame.cmd`.
2. **Project → Export → Add → Windows Desktop**. Используйте обычную архитектуру x86_64 и релизный экспорт.
   В разделе Resources исключите из экспорта `tests/*`, `tools/*`, `docs/*`, `test-results/*`, `graphify-out/*`, `art-source/*`. Папку `assets/` оставьте включённой.
3. Экспортируйте в отдельную папку `builds/windows/`. Не распространяйте `.godot/`, `test-results/` и `graphify-out/`.
4. Если PCK лежит отдельно, передайте другу и EXE, и PCK из одной сборки. После установки новых шаблонов сначала проверьте сборку на своём ПК.
5. Повторите LAN-тест уже в экспортированных приложениях. Путь EXE для Windows Firewall изменится по сравнению с редактором.

Готовая экспортированная EXE-сборка пока не включена: проект запускается установленным Godot через стартовый файл. Не нужно устанавливать Steam или сетевые плагины.

## Graphify

Локальный анализ запускался с `GRAPHIFY_BACKEND=none` и `--code-only --max-workers 2`. Текущая установленная версия не распознаёт `.gd` и `.tscn`. Граф охватывает Python-инструменты запуска тестов и создания моделей; его нельзя использовать как доказательство связей игрового кода.

Игровой код проверялся по исходникам и работающим экземплярам Godot. `graphify-out/` исключён из Git через `.gitignore`; Git-репозитория на момент создания проекта в этой папке не было. Семантические бэкенды, загрузка исходников и внешние модели не использовались.
