# Проверки 0.6

Проверено на Windows 28 октября 2026, Godot 4.7.2.stable.official.ed1daf0bf. Headless-проверки оформления, новых секторов и прежних механик завершились ART_PASS, SECTOR_PASS, FEATURE_PASS. Настоящие ENet-сценарии на 2 и 4 процессах прошли полный жизненный цикл. Это локальные процессы одного компьютера; Wi-Fi и брандмауэр на двух физических ПК нужно проверять отдельно.

## Запуск

Godot должен быть доступен через GODOT_BIN, PATH godot4/godot или аргумент --godot. Python нужен только инструментам разработки.

```sh
python tools/run_smoke.py --players 2 --godot /path/to/Godot
python tools/run_smoke.py --players 4 --port 27942 --godot /path/to/Godot
```

Проверки Godot из корня проекта после импорта:

```sh
godot --headless --editor --path . --import --quit
godot --headless --path . -- --art-check
godot --headless --path . -- --sector-check
godot --headless --path . -- --feature-check
```

Подставьте свой путь вместо godot. Используйте отдельный локальный каталог настроек для тестов. LAN-запускатель изолирует настройки участников через --test-user-dir; обычная игра этот аргумент не использует. Логи сохраняются под test-results, папка исключена из импорта и Git.

## Что покрыто

- Импорт 42 моделей, скелет, 11 клипов, снижение головы при беге на четвереньках.
- Пресеты графики, путь к новым фактурам и записанным звукам.
- Маска пола, маршруты между секторами, запертый и открытый шлюз D.
- Поворотные двери B/C, навигация створки, настоящая погоня через проход.
- Решение давления, перебор решений схемы, отказ недопустимым индексам и удалённым командам.
- Подбор запертого фильтра, урон токсичной зоны, непрерывное удержание очистки, частота и условия финала.
- Альфа текстуры следа, разные ноги, ограничение числа экземпляров.
- Смена ролей, репликация движения, ограничение ввода и защита от NaN/чужого раунда.
- Реальный подбор, расход предметов, генератор, архив и доставка состояния клиентам.
- Реакция сущности в упор со спины, открывание дверей и естественный саботаж после ожидания.
- Выстрел, отсутствие прострела стены, патроны, перезарядка, падение на 60 секунд и восстановление.
- Падение игрока, рост крови, SOS/пауза, поднятие, окончательная гибель и настройки управления/аудио.
- Кооперативный финал с двумя разными операторами, выход клиента и возврат вещей, повторный раунд, проигрыш по времени.

Сценарий --preview временно открывает настоящий рендер и сохраняет меню, новые сектора, монстра в трёх позах, следы, карту, головоломку, раненого и настройки, затем выходит. Использует Compatibility на Intel UHD. Кадры FPS не являются обещанием производительности.

## Настольные платформы

.github/workflows/desktop.yml скачивает официальный Godot и выполняет импорт, art/sector/feature и LAN-2 нативно на Windows, Linux и macOS. tools/ci_check.py не требует внешних Python-пакетов. Наличие workflow не означает, что все его задания уже прошли: проверяйте результат конкретного коммита в GitHub Actions.

Unix-скрипты проверяются sh -n и режимом --check, в том числе с кириллицей и пробелами в пути. Нативная графика Linux/macOS и смешанная LAN между ОС требуют отдельного запуска на соответствующих компьютерах. Мобильные платформы и браузер пока не поддерживаются.

Три export_presets.cfg исключают тесты, инструменты, исходники Blender и сырые аудио. Для проверки содержимого экспортированного PCK есть внешний tests/package_check.gd: он проверяет JSON-банк, все модели и аудиоклипы, лицензии, отсутствие файлов разработки. Сам этот скрипт в сборку не входит. Чистая копия без .godot прошла импорт и SECTOR_PASS. Экспорт PCK для Windows/Linux/macOS завершился без ошибок; проверка содержимого Windows PCK из отдельного каталога дала PACKAGE_PASS. Экспорт PCK не равнозначен выпуску готового исполняемого файла: для него нужны шаблоны 4.7.2.

## Ручное прохождение

Завершите раунд с обычным перемещением без тестовых телепортов. Проверьте связь двух физических ПК, смену ролей, ремонт аварии, лечение, выстрел, поиск патронов и распределение операторов между A и D. Затем повторите с обновлённым кодом и после переподключения. Длительный баланс, слабый Wi-Fi и разные драйверы остаются предметом ручной проверки.

## Graphify

Граф локальный, GRAPHIFY_BACKEND=none, extract . --code-only --max-workers 2. Установленная версия не разбирает .gd и .tscn: граф используется для Python-инструментов и не доказывает связи игрового GDScript. Его вывод сверяется с текущими исходниками и Godot-проверками. graphify-out исключён из Git.
